# 泡泡堂多人在线小游戏 · 设计文档

- 日期：2026-08-30
- 状态：待用户确认
- 项目目录：`E:\boss\paopaotang`

## 1. 目标

做一个类似经典 4399 泡泡堂的网页版多人在线对战游戏：

- 2 人或 4 人实时对战，通过放泡泡炸箱子、炸对手，最后存活者获胜
- 两种开局方式：**快速匹配**（选 2 人/4 人局，凑齐自动开局）和 **创建/加入房间**（房间号邀请朋友）
- 第一阶段在本机/局域网可玩（多浏览器窗口联机），架构上保证后续可以直接部署到云服务器

## 2. 非目标（第一阶段明确不做）

- 账号系统、战绩、排行榜、皮肤商店
- 正式公网部署（但服务器独立成包，部署时零重构）
- 移动端触屏操作（键盘鼠标为主；后续可加虚拟摇杆）
- AI 机器人、观战模式、游戏内聊天

## 3. 技术栈

| 层 | 选择 | 理由 |
|---|---|---|
| 服务端 | Node.js 20+ / TypeScript / Colyseus | 房间生命周期、状态同步、断线重连内置，最契合房间制小游戏 |
| 客户端 | Vite / TypeScript / 原生 Canvas 2D | 纯 2D 网格游戏，不需要 Unity/Cocos 重引擎 |
| 共享代码 | npm workspaces 的 `shared` 包 | 格子尺寸、速度、爆炸时长等常量和类型前后端共用一份，避免两边不一致 |
| 测试 | vitest | 服务端规则逻辑全部可单测 |

## 4. 总体架构

**权威服务器模式**：所有游戏逻辑（移动碰撞、泡泡倒计时、爆炸范围、道具掉落、死亡判定、胜负）只在服务器算。客户端只做两件事：

1. 发送操作意图（按下/松开方向键、放泡泡）
2. 渲染服务器同步来的状态

好处：逻辑只有一份、天然防作弊、客户端代码简单。

**同步方式**：Colyseus Schema 状态同步。服务器内部 60Hz tick 模拟，以约 15Hz 的频率向客户端广播增量状态；客户端对其他玩家的位置做插值使画面平滑。第一阶段本地玩家不做客户端预测（局域网/本机延迟无感；公网优化留作后续迭代）。

**通信内容**：

- 客户端 → 服务器：`move`（方向按下/松开）、`bomb`（放泡泡）
- 服务器 → 客户端：Schema 状态增量（玩家、泡泡、道具、火焰、阶段）+ `gameOver` 结算消息

## 5. 游戏规则

**地图**

- 13×11 格；外圈为硬墙（不可炸）；内部按棋盘格规律布置硬墙；内部非硬墙、非安全区的格子约 70% 放软墙（可炸）
- 4 个出生点在四角，各带 3×3 无软墙安全区；开局保证每个出生点至少有一条可走出安全区的通路
- 地图由服务器随机生成，布局作为状态同步给客户端

**玩家**

- 初始属性：泡泡数 1、火焰长度 1、速度档 1（约 4 格/秒，上限 6 档）
- 出生后 2 秒无敌（闪烁提示），期间不受火焰伤害
- 移动采用"格到格"插值：从一个格子中心移动到相邻可通行格子中心，到达后才可变更方向；碰撞判定因此退化为"目标格是否可通行"，简单且对所有人公平

**泡泡与爆炸**

- 空格放泡泡（占用数量上限），2.5 秒后爆炸
- 爆炸产生十字火焰，长度 = 火焰属性；被硬墙挡住；烧到软墙则摧毁软墙并在该格停止
- 连锁：火焰碰到其他泡泡立即将其引爆（递归）
- 火焰持续 0.5 秒；火焰碰到道具会将其烧毁

**道具**（软墙被炸后 30% 概率掉落）

- 泡泡+1（上限 8）、火焰+1（上限 8）、速度+1（上限 6），踩到立即生效

**死亡与胜负**

- 玩家被火焰碰到即死，不复活
- 最后存活者获胜；若最后一瞬间多人同时死亡则为平局
- 开局 3 分钟后进入**突然死亡**：硬墙从外圈每隔 5 秒向内合拢一圈，把地图逐渐挤满，杜绝无限拖延

## 6. 数据结构（Colyseus Schema）

```
GameRoomState
├─ phase: "waiting" | "playing" | "ended"
├─ roundEndsAt / suddenDeathAt: number   // 服务端时间基准，客户端做倒计时显示
├─ grid: string                          // 地图布局编码（每格一字符：硬墙/软墙/地板）
├─ players: MapSchema<Player>
│    └─ { id, name, colorIndex, x, y, dir, moving,
│         bombs, flames, speed, alive, invincibleUntil, connected }
├─ bombs: MapSchema<Bomb>      // { id, gx, gy, power, explodeAt, ownerId }
├─ explosions: MapSchema<Explosion>  // { id, cells: number[], expireAt }（瞬时对象）
├─ items: MapSchema<Item>      // { id, gx, gy, type }
└─ winnerIds: string[]
```

坐标约定：地图格子坐标 `gx, gy` 为整数；玩家 `x, y` 为格坐标浮点值（渲染时乘格子尺寸）。

## 7. 大厅、匹配与房间流程

- 大厅页：输入昵称 → 两个入口
  - **快速匹配**：选 2 人/4 人局 → 进入匹配队列 → 凑齐自动开局；等待超过 30 秒提示改用创建房间
  - **创建房间**：生成 4 位房间号；其他玩家输入房间号加入；房主可随时点"开始"（不满员也能开局，方便先 2 人玩）；满员自动开局
- 匹配用 Colyseus 的 `matchMaker` + 自定义队列逻辑实现（一个常驻的 MatchQueueRoom 负责凑人并调用 `createRoom` 预留席位）

## 8. 客户端渲染与输入

- Canvas 2D，格子 32px；地图 416×352px，上方 HUD 显示存活人数/倒计时，下方操作提示
- 渲染层次（从底到顶）：地板/硬墙/软墙 → 道具 → 泡泡 → 火焰 → 玩家 → 死亡特效
- 玩家用 4 种颜色区分（红/蓝/黄/绿），第一阶段用 Canvas 绘制的简单形状当占位，之后换 Kenney（CC0）素材
- 输入：方向键或 WASD 移动，空格放泡泡；**状态变化时**才发消息（按下/松开），不是每帧发
- 音效：第一阶段用 Web Audio 合成几个简单音效（放泡/爆炸/捡道具/死亡），或直接用素材包

## 9. 错误与边界处理

- **断线重连**：Colyseus `allowReconnection`，30 秒内重连恢复原状态；超时判该玩家死亡并移出房间
- **游戏中途有人退出**：其余玩家继续对局
- **匹配队列超时**：30 秒凑不齐人给出提示
- **服务器崩溃**：第一阶段不做恢复（单进程，重启即失）；上线阶段再考虑持久化与多进程

## 10. 测试策略

- 服务端规则逻辑（地图生成合法性、爆炸范围、连锁引爆、道具掉落与生效、死亡判定、突然死亡、胜负）用 vitest 写单元测试——这是整个项目正确性的核心
- 客户端把插值、渲染坐标换算写成纯函数便于测试
- 联机验收：本机开 4 个浏览器窗口实际对局；再用两台设备连同一局域网验证

## 11. 里程碑（每步结束都可运行）

1. **M1 单机能玩**：地图渲染、角色移动、放泡泡、泡泡爆炸与火焰（无网络）
2. **M2 规则完整**：软墙掉道具、连锁爆炸、死亡判定、无敌时间（本机单人跑图验证）
3. **M3 联机对战**：逻辑搬进 Colyseus 服务器，本机多窗口 2~4 人真实对战
4. **M4 大厅与收尾**：快速匹配、房间号、结算画面、突然死亡、断线重连
5. **M5 表现升级**：Kenney 素材替换占位图形、音效
